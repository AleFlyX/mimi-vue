## reactive函数创建一个响应式对象，它接受一个普通对象作为参数，并返回一个代理对象。这个代理对象会拦截对原始对象的访问和修改操作，从而实现响应式数据的功能。

## 概述
在 reactive 函数中，我们首先定义了一个枚举 ReactiveFlags，用于标记代理对象已经被代理过了。然后，我们定义了一个 mutableHandlers 对象，它包含了 get 和 set 方法，这些方法定义了当访问或修改代理对象的属性时应该执行的操作。在 get 方法中，如果访问到 ReactiveFlags.IS_REACTIVE 属性，就直接返回 true，表示这个对象已经被代理过了。否则，使用 Reflect.get 来获取目标对象的属性值。在 set 方法中，首先使用 Reflect.get 来获取目标对象当前的属性值，如果新值和旧值相同，就直接返回 true，表示设置成功。否则，使用 Reflect.set 来设置目标对象的属性值，并返回设置结果。

## 代码分析
```typescript
/**
 * mutableHandlers 是一个包含 get 和 set 方法的对象，这些方法定义了当访问或修改代理对象的属性时应该执行的操作。
 * 在 get 方法中，如果访问到 ReactiveFlags.IS_REACTIVE 属性，就直接返回 true，表示这个对象已经被代理过了。
 * 否则，使用 Reflect.get 来获取目标对象的属性值。
 * 在 set 方法中，首先使用 Reflect.get 来获取目标对象当前的属性值，如果新值和旧值相同，就直接返回 true，表示设置成功。
 * 否则，使用 Reflect.set 来设置目标对象的属性值，并返回设置结果。
 */
export const mutableHandlers:ProxyHandler<any>={
    get(target,key,receiver){ //receiver是代理对象本身
        if(key===ReactiveFlags.IS_REACTIVE) return true;//检查是否为已经被代理过的
        return Reflect.get(target,key,receiver);
    },
    set(target,key,value,receiver){
       if(Reflect.get(target,key,receiver)===value)
       {
            return true;
       }
        return Reflect.set(target,key,value,receiver);
    }
}
```

## 注意事项
1. 在 get 方法中，使用 Reflect.get 来获取目标对象的属性值时，需要传入 receiver 参数，这样才能正确地处理代理对象的继承关系。
2. 在 set 方法中，使用 Reflect.get 来获取目标对象当前的属性值时，也需要传入 receiver 参数，以确保获取到的是代理对象的属性值，而不是原始对象的属性值。
3. 在 set 方法中，如果新值和旧值相同，就直接返回 true，表示设置成功，这样可以避免不必要的更新操作，提高性能。
4. 通过在代理对象上设置一个特殊的属性来标记它已经被代理过了，这样在后续的操作中就可以通过这个属性来判断对象是否已经被代理过了，避免重复代理。
5. 这个 mutableHandlers 对象可以被 reactive 函数用来创建代理对象，从而实现响应式数据的功能。

## 问题：
#### 为什么proxy的get方法中需要传入receiver参数？
在 JavaScript 中，Proxy 的 get 方法接受三个参数：target、key 和 receiver。 其中，receiver 是指向代理对象本身的引用。当我们访问代理对象的属性时，get 方法会被调用，并且 receiver 参数会被传递给 Reflect.get 方法。 这是因为在某些情况下，代理对象可能会被继承或者被其他对象引用，这时我们需要确保在 get 方法中获取到的是代理对象的属性值，而不是原始对象的属性值。 通过传入 receiver 参数，Reflect.get 方法能够正确地处理代理对象的继承关系，确保我们获取到的是代理对象的属性值，从而实现响应式数据的功能。

#### 为什么要用Reflect.get来获取目标对象的属性值，而不是直接访问目标对象的属性？
使用 Reflect.get 来获取目标对象的属性值，而不是直接访问目标对象的属性，有几个原因：
1. Reflect.get 是一个内置的 JavaScript 方法，它提供了一种更安全和可靠的方式来访问对象的属性。它可以正确处理代理对象的继承关系，确保我们获取到的是代理对象的属性值，而不是原始对象的属性值。
2. Reflect.get 可以处理一些特殊情况，比如访问一个不存在的属性时，它会返回 undefined，而不是抛出一个错误。这使得我们的代码更加健壮，避免了不必要的错误。
3. 使用 Reflect.get 可以让我们更好地控制访问对象的属性，比如我们可以在 get 方法中添加一些额外的逻辑，比如检查属性是否存在，或者进行一些权限验证等。这些都是直接访问目标对象的属性所无法实现的。
因此，使用 Reflect.get 来获取目标对象的属性值，可以让我们的代码更加安全、可靠和灵活，从而更好地实现响应式数据的功能。
##### 错误示例代码：
```javascript
const person = {
    a: 1,
    get b(){
        return this.a + 1;
    } 
};
const proxy = new Proxy(person, {
  get(target, key, receiver) {
    console.log('get key:',key);
    return target[key]; // person.b方法中的this.a调用时不会触发get方法，所以只会输出 get key: b 2，而不会输出 get key: a。
  }
});

console.log(proxy.b); // 输出 get key: b 2
// 问题：因为b方法会调用a属性，按理来说应该输出 get key: a 和 get key: b 2，但实际上只输出了 get key: b 2。这是因为在 get 方法中，我们直接访问了目标对象的属性，而没有使用 Reflect.get 来获取属性值。 从而做到在b方法中访问a属性时，触发get方法，输出 get key: a 1 和 get key: b 2。

//假如你为了简单解决，使用receiver参数来获取属性值，代码如下：
const proxy = new Proxy(person, {
  get(target, key, receiver) {
    console.log('get key:',key);
    return receiver[key]; // 这样做，访问proxy.b时会导致死循环，因为在 get 方法中访问 receiver[key] 时，又会触发 get 方法，从而导致无限递归调用，最终导致栈溢出错误。
  }
});
```

##### 正确示例代码：
```javascript
const person = {
    a: 1,
    get b(){
        return this.a + 1;
    } 
};
const proxy = new Proxy(person, {
  get(target, key, receiver) {
    console.log('get key:',key);
    return Reflect.get(target, key, receiver); // 使用 Reflect.get 来获取属性值，这样在 b 方法中访问 a 属性时，也会触发 get 方法，输出 get key: a 1 和 get key: b 2。
  }
}); 
console.log(proxy.b); // 输出 get key: a 1 和 get key: b 2
```
